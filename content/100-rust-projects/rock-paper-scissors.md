# Project 012 – Rock-Paper-Scissors Game

## Code
Runs an interactive game loop of Rock-Paper-Scissors against the computer, using random indices for computer choices, verifying user input, and maintaining running scores.

---

## Problem
Interactive gaming requires parsing structured string choices, matching combinations, generating pseudo-random index selections, maintaining session scores, and handling exits.

---

## Goal
Build a terminal game loop that parses user inputs, matches them against enum-structured rules, evaluates results, and tracks scores until the user chooses to quit.

---

## What I Learn
- Tail recursion usage in functions like `get_user_choice` to repeat prompts on invalid inputs
- Selection from fixed-size arrays (`[&str]`) using random indices generated by `rand::thread_rng().gen_range`
- Custom `enum` structures to represent state conditions (`Win`, `Lose`, `Draw`)
- Multi-variable tuple matching (`match (user, computer)`) to cleanly evaluate game logic rules
- Pattern matching guards with `if` qualifiers to resolve draw cases
- Standard text parsing to normalize strings to lowercase before comparisons
- Mutable integer accumulators to keep session-wide score state

---

## Notes
- Tail recursion in Rust is not guaranteed to be optimized away (Tail Call Optimization); for deeply nested inputs, loops are preferred to avoid stack overflow.
- Declaring array selections using references (`&str`) avoids allocating new strings for static choices.
- Try adding a round count tracker and implementing a "best of three" condition to declare an overall winner.
